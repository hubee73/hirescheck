# hirescheck — 高采样率 PCM / DSD 来源检查

**中文** | [English](README.en.md)

对 PCM 文件，hirescheck 回答的是：**高采样率文件（如 96k/192k）是不是从较低采样率升频来的、大概来自哪个采样率，文件是否带有超出 48kHz 采样所能保留的频率信息，以及转换为 48kHz 后损失了多少能量。** 它不能仅凭一个文件证明 192kHz 听起来明显更好，也不能鉴定录音的真实来源。

对 44.1kHz / 48kHz 的文件（常见的“CD 无损”），它回答：**是不是由 MP3、AAC、Opus、Vorbis 等有损文件转成无损格式的。**

加上 `--check-sr` 时，还会回答：**高解析文件的超声部分是不是由某条已知的加工链做出来的**（例如某个来源出品的、超声部分其实是加工出来的 192k 文件），见“加工链检查”。

对 DSD 文件（DSF、DFF，包括 DST 压缩的 DFF），它回答：**是不是从 PCM 转过来的、PCM 来源大概是什么采样率，以及是不是从低倍率 DSD 升上来的（例如 DSD64→DSD128）。**

支持 FFmpeg 能解码的 PCM、无损格式与 DSD：FLAC、WAV、AIFF、ALAC、APE、WavPack、DSF、DFF 等。格式按文件实际内容识别，不看扩展名。

## 安装

需要：
- Python 3.10 或更新版本；
- FFmpeg（`ffmpeg` 与 `ffprobe`）：macOS 用 `brew install ffmpeg`，Debian/Ubuntu 用 `sudo apt install ffmpeg`，Windows 用 `winget install Gyan.FFmpeg`。

**用 pipx 安装**（推荐，任何系统都可以；在项目目录里运行）：

```bash
pipx install ".[plot]"      # 不要频谱图就去掉 [plot]
```

**用安装脚本**（macOS / Linux，在项目目录里运行）：

```bash
./install.sh            # 完整安装
./install.sh --no-plot  # 不装 matplotlib，不生成频谱图
```

安装脚本会：
1. 检查 Python、venv、ffmpeg/ffprobe，以及 FFmpeg 是否支持 FLAC 和 DSD 解码。缺什么就提示对应系统的安装命令；FFmpeg 不支持 DSD 时只给警告，PCM 检查不受影响。
2. 在 `~/.local/share/hirescheck/.venv` 建虚拟环境（设置了 `XDG_DATA_HOME` 时放在 `$XDG_DATA_HOME/hirescheck/`），把 hirescheck 连同 numpy、scipy、matplotlib 装进去。
3. 生成启动器 `~/.local/bin/hirescheck`。如果 `~/.local/bin` 不在 PATH 中，会提示要加到哪个配置文件。

更新代码后重新运行 `./install.sh` 即可：程序会被重新安装，能用的虚拟环境会保留。想换 Python 版本，用 `PYTHON=python3.12 ./install.sh` 指定解释器，这时会用它重建虚拟环境。卸载用 `./install.sh --uninstall`，只删除上述两处，不会删除报告。

安装脚本不会覆盖已有的、不是它生成的 `~/.local/bin/hirescheck`。

**Windows** 没有安装脚本，用 pipx，或者手动建虚拟环境：

```powershell
winget install Gyan.FFmpeg     # 装好后重新打开终端
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install ".[plot]"
.\.venv\Scripts\hirescheck.exe "D:\音乐\歌曲.flac"
```

## 使用

```bash
hirescheck "/路径/歌曲.flac"                          # 报告写到 ./歌曲_hirescheck/
hirescheck "/路径/专辑/01.dsf" --out "检查结果"
hirescheck "歌曲.flac" --max-seconds 60               # 只看开头一分钟；报告会注明只扫描了开头
hirescheck "歌曲.flac" --compare-seconds 60           # 加长 48kHz 差分的选段
hirescheck "歌曲.flac" --compare-seconds 0 --no-plot  # 只做频谱检查，不做差分、不绘图
hirescheck "歌曲.flac" --check-sr                     # 另外比对已知加工链的指纹
hirescheck "歌曲.flac" --lang en                      # 用英文输出
hirescheck --version
```

**输出语言**默认跟随系统：`LC_ALL`、`LC_MESSAGES`、`LANG` 中第一个设置了的是中文（`zh_*`）就用中文，否则用英文；macOS 上没有设置这些变量时看系统语言。用 `--lang zh` 或 `--lang en` 可以指定，`--help` 也会随之切换。

### 检查整个文件夹

参数也可以是文件夹，可以传多个，也可以和文件混着传。文件夹会递归扫描：

```bash
hirescheck "/路径/专辑"                        # 报告写到 ./专辑_hirescheck/
hirescheck ~/Music -j 4 --out ~/音乐检查报告    # 同时分析 4 个文件
hirescheck "专辑1" "专辑2" "单曲.flac"          # 多个输入时默认写到 ./hirescheck_reports/
```

- **扫描哪些文件**：只按扩展名挑选音频，包括 `.flac .wav .wave .w64 .rf64 .aif .aiff .aifc .caf .m4a .alac .mka .ape .wv .tta .tak .dsf .dff`。
- **跳过哪些文件**：
  - 隐藏文件和文件夹，以及 macOS 拷贝时留下的 `._xxx.flac`；
  - 指向文件夹的符号链接不会跟进，避免循环；
  - 探测出是有损编码（例如 `.m4a` 里的 AAC）的文件，在汇总里记为“已跳过”。单独指定一个文件时，不管扩展名和编码，都照常分析。
- **报告目录**：每个文件一个子目录，结构和原文件夹一致，比如 `专辑_hirescheck/CD1/01 歌名/`。同一目录下有同名不同格式的文件（如 `01.flac` 和 `01.dsf`）时，子目录名会带上扩展名，例如 `01_flac/`。报告只写到报告目录里，不会往音乐文件夹里写东西。
- **汇总**：根目录下生成 `summary.csv` 和 `summary.txt`，每个文件一条，包括一句话的通俗结论、各问题的可能性等级、格式、推断的来源采样率、技术判断和报告位置。`summary.csv` 带 BOM，用 Excel 打开中文不会乱码。
- **出错处理**：单个文件出错（损坏、无法解码）只在汇总里记为“出错”，不中断整批。
- **并行**：`-j N` 同时分析 N 个文件。实测 4 核机器上一张 28 首的 CD 专辑约 1 分钟。每个任务的内存峰值实测约 250MB（192k FLAC 和 DSD128 都差不多，因为是分块读取），`-j` 不宜超过 CPU 核数。

不安装也可以在项目目录里直接运行：`python -m hirescheck "歌曲.flac"`（要先装好 numpy 和 scipy，画图还要 matplotlib）。

解码交给 FFmpeg：以文件自身的采样率和声道数输出 64 位浮点 PCM，不做重采样、混声道或抖动，整数样本转成浮点是精确的。

默认扫描全曲，按块解码，不会把整首音频载入内存。频谱窗长 32768、50% 重叠，192kHz 下分辨率约 5.86Hz。声道按功率平均，避免左右反相导致误判。极静窗口按相对电平和绝对电平门限排除，具体门限写入报告。48kHz 差分默认从扫描范围中均匀选最多三个片段，总计约 24 秒；DSD 文件不做差分。

输入不高于 48kHz 时不做升频判断和差分，改做有损编码检查，见下文。

## 输出

默认在当前工作目录创建 `<歌曲名>_hirescheck/`，也可用 `--out` 指定目录。重复运行会覆盖该目录内的同名报告，不修改输入音频。

| 文件 | 内容 |
| --- | --- |
| `report.txt` | 开头是给普通读者的“结论”，后面是“技术细节”：能量表、截止点、有损检查和差分结果 |
| `report.json` | 机器可读的测量结果、判定门限、声道数据和选段位置；`plain` 字段是通俗结论 |
| `spectrum.png` | 平均频谱、全曲频谱随时间变化、可听/超声频段的电平曲线 |
| `spectrum.csv` | 各声道及平均功率谱密度，单位 dBFS/Hz |

`plot_generated` 与 `plot_status` 记录本次是否绘图；关闭绘图或缺少 matplotlib 时，不删除目录中上次生成的 PNG，请以本次 JSON 为准。报告文字使用 UTF-8，语言见上面的“输出语言”；`report.json` 的 `language` 字段记录用的是哪种语言，可能性等级另存为与语言无关的代码（`very_high`、`high`、`unsure`、`low`、`very_low`、`unknown`），方便程序处理。频谱图内一律用英文，以免系统缺少中文字体。

## 怎么读结果

报告开头的“结论”用大白话回答两三个问题，例如：

```
结论
------------------------------------------------------
像是真正的高解析录音：含有 CD/48kHz 记录不到的高频。

  经过有损压缩（MP3/AAC 等）：可能性很低
      有损格式会把 20kHz 左右以上的声音切掉，而这个文件的高频一直延伸到 24kHz 以上，还跟着音乐起伏。
  由低采样率升频到 192kHz：可能性较低
      文件里有 24kHz 以上的声音（CD 和 48kHz 录音记录不到这一段），而且跟着音乐一起起伏……
```

会回答的问题：
- **PCM 文件**：有没有经过有损压缩；采样率是不是被提升过，如果是，原始采样率大约是多少。
- **DSD 文件**：是不是由普通 PCM 音频转成的，如果是，来源大约是多少采样率；是不是由低规格 DSD 提升上来的。

“可能性”分为 **很高 / 较高 / 说不准 / 较低 / 很低**，另外还有“无法判断”。这些是按证据强弱分的等级，**不是统计概率**：
- 要给出“90%”这样的数字，需要一大批来源确定的真实曲目做统计，现在没有这样的数据；
- 有些情况本身就分不开，例如 44.1kHz 和 48kHz 的来源经常无法区分，硬给两个百分比只会误导人。

后面“技术细节”里的判断代码和各项数值，供想深入核对的人参考。下面按文件类型说明各种技术判断。

### 44.1kHz / 48kHz 文件

- **疑似有损来源**（`lossy_suspect`）：平均谱在 20.5kHz 以下有陡峭截止，或 16kHz 以上有明显的频谱空洞。报告会给出截止位置和接近的编码器码率，比如“接近 MP3 320kbps、Opus 或高码率 Vorbis 的低通”。母带主动低通、老录音、降噪处理也会产生截止，需要结合来源判断。
- **未见有损迹象**（`no_lossy_sign`）：没有找到上述迹象，并给出有多少响亮片段延伸到 20kHz 以上。空洞比例在 0.5–1% 之间时会额外注明“接近门槛”，值得打开频谱图看一眼。**高码率 AAC（256kbps 以上）的频谱可能和无损一样，因此无法排除。**

**24kHz 是比较 48kHz 采样的关键边界。** 48kHz 的奈奎斯特频率为 24kHz。20–24kHz 也是 48kHz 的频宽范围，不能把它算成 192kHz 独有的信息。脚本额外报告 >26kHz 的能量，以便避开实际转换滤波器的过渡区域。

- **与 X kHz 来源升频一致**（`upsampled`）：内容在某处陡降，之上几乎为空、只有与通带对称的镜像，或只有先空出一段再上升的噪声。报告给出最可能的来源采样率；滤波器较缓时会写“也可能 Y kHz”。若更高处还有第二个截止，会提示可能经过的中间采样率。原生高采样率录音经过同样的低通也会这样，不能直接认定造假。
- **疑似有损来源或严重限带**（`band_limited_low`）：截止低于 19kHz，例如 MP3 转出后再升频。
- **截止不对应常见采样率**（`band_limited_nonstandard`）：可能是母带低通或非常规转换。
- **未检出显著的 >24kHz 能量**：既没有超声能量，也没有找到明确的截止；没有看到保留 192kHz 的理由，来源仍不确定。
- **存在超声能量，呈噪声特征**：可能有宽带噪声、噪声整形等；能量存在不代表额外音乐信息。
- **检测到超出 48kHz 频宽的能量**：只能说明超声能量存在。乐器泛音、设备噪声、DSD 转 PCM、后期失真甚至主动添加的噪声都可能产生它。
- **证据不确定/不足**：信号过弱、片段太短或数据接近经验门限，应结合频谱图查看。

### 升频检测怎么做

在全曲平均谱上从 10kHz 往上连续扫描，不再只看预设位置。把频谱按 100Hz 分组取平均，比较每个位置下方和上方一段的中位数：用 0.3–1.5kHz 的窗口抓陡峭的滤波器，用 1–3kHz 的窗口抓过渡带较缓的滤波器。满足以下条件才算一个**频宽上限**：

- 下降 ≥25dB，斜率 ≥120dB/倍频程。模拟或母带滚降通常只有 12–48dB/倍频程，不会被当成截止。
- 截止以上满足四种情况之一：
  - 90 分位电平比截止前低 ≥20dB；
  - 残留与通带呈镜像（升频滤波器留下的镜像）；
  - 先空出约 8kHz，之后只有随频率上升的噪声（噪声整形，例如经 DSD 转换的 PCM 母带）；
  - 截止落在标准采样率的奈奎斯特频率附近、深度 ≥30dB，上方仍有较弱的能量但至少低 6dB。这种情况常见于廉价升频的镜像，或升频后又加了噪声。

**量化/抖动底噪的台阶同样算数。** 16bit 来源的抖动底噪约 -140dBFS/Hz，升到 24bit 后，原奈奎斯特频率以上会跌到 -180dBFS/Hz 以下。所以即使录音本身几乎没有高频，也能看到截止。

**来源采样率**根据截止的起点或中点推断：两者之一落在某个标准采样率奈奎斯特频率的 80%–103% 即可（截止前高频已在下滑时起点会偏低，滤波器较缓时中点会偏高）。多个候选时，截止中点最接近奈奎斯特频率 97.5% 的排在前面：陡峭的重采样器把中点放在奈奎斯特频率稍下方，FFmpeg 的 swr 则放在它附近。过渡带较宽时，44.1k 与 48k 常无法区分，报告会同时列出。

**镜像检测**：线性插值这类廉价升频几乎不衰减镜像，频谱会在原奈奎斯特频率处“对折”回来，看不到陡降。脚本单独比较 22.05k、24k 等位置两侧的频谱形状，相关系数 ≥0.9 即视为镜像。自然频谱随频率下降，与自身镜像呈负相关，因此不容易误判。

**多级升频**（例如 44.1k→96k→192k）只有在中间步骤留下痕迹（镜像、噪声或第二个截止）时才能看出；每一步都转换干净时，在数学上与一次直接升频无法区分。

这些门限是用合成样本和一张真实 SACD 调出来的经验值，全部写入 `report.json` 的 `heuristics`。已知局限：滤波器很缓、录音又几乎没有高频时，镜像落在平坦的底噪上，可能检不出升频。

超声能量相对可听频段低于 -75dB，**或**绝对 RMS 低于 -95dBFS，会被归入“很少”；高于 -65dB 且绝对 RMS 高于 -95dBFS，可视为明确检测到能量。这些是经验筛选门限，**不是听觉阈值或鉴定置信度**。谱平坦度与随音乐电平变化的相关性只提供线索，不能分离音乐与噪声。

明确检测到超声内容的自动标签使用 **>24.5kHz** 的保护边界，减少恰好在 24kHz 附近的信号经 FFT 泄漏造成的误判；原始 >24kHz 和 >26kHz 测量仍分别报告。仅在截止边缘附近有能量时，可能输出“不确定”。数值低于 -300dB 的读数统一显示为 -300dB，表示数值显示下限。

### 有损检测怎么做

有损编码器为了省码率，会在 16–20.4kHz 加一道陡峭的低通；心理声学模型还会根据音乐内容随时丢掉部分高频，在频谱图上留下一块块空洞。检查用两路分析：

- **截止**：在全曲平均谱的 14–20.5kHz 内，比较每个位置下方 0.1–0.8kHz 与上方 0.1–0.8kHz 的中位电平，落差 ≥25dB 且截止前的电平明显高于字长对应的量化底噪，就算有损截止。CD 母带常见的抗混叠滤波器在 20.75kHz 以上，不计入。
- **频谱空洞**：用约 93ms 的短窗逐段分析，只看响亮片段。统计 16kHz 到内容上限之间，有多少时频点比该频点自身的中位数低 30dB 以上，达到 1% 就算有损迹象。编码器丢弃的通常只是部分频段；如果某个片段一半以上的高频同时消失（音乐停顿、门限处理过的镲片），那是音乐本身，不计入。

这些门限用 4 首 CD 原盘（两首 Adele、两首 Beyond）和它们的 13 种有损转码校准：

| 来源 | 检出 |
| --- | --- |
| 原盘（空洞 0.00–0.04%） | 0/4 误判 |
| MP3 128/192/256/320kbps、VBR V0/V2 | 24/24 |
| AAC 128kbps、Opus 128/192kbps、Vorbis q6 | 16/16 |
| Vorbis q9（约 320kbps） | 2/4 |
| FFmpeg AAC 256/320kbps | 0/8：截止在 20.8–21kHz，与 CD 滤波器重合，空洞也少 |

因为是在同一批文件上校准的，这个表反映的是规则能区分到什么程度，不是在陌生曲库上的准确率。

另用一首没参与校准的 1961 年爵士磁带录音（DSD256 转出的 44.1kHz CD 版本）做了独立验证：原版未误判，MP3 320k、AAC 128k、Opus 160k 都检出；MP3 V0 和 AAC 256k 没检出。V0 的低通在约 21kHz，和 CD 版本自身的滤波器重合，这首录音的高频又弱，留下的空洞只有 0.27%。所以在高频较弱的录音上，VBR V0 这类高质量 MP3 也可能漏检。在一个 100 首 44.1/48k 的真实曲库上，空洞比例的中位数是 0.002%，超过 0.5% 的只有少数几首。

## DSD 检测怎么做

FFmpeg 把 DSD 解码为 1/8 比特率的 PCM（DSD64 → 352.8kHz）。它的降采样滤波器只在解码后奈奎斯特频率的一半以内保真（误差 <1dB），所以只分析到这里：DSD64 为 88.2kHz，DSD128 为 176.4kHz。

任何 DSD 都是 sigma-delta 调制器的输出，噪声整形会把量化噪声推到超声区，所以“有随频率上升的噪声”本身不能区分真假。脚本看的是另外两点：

- **PCM 来源**：在调制噪声抬起之前，寻找与 PCM 检测相同的频宽截止。PCM 转成的 DSD 典型表现是：内容在原奈奎斯特频率前陡降，之后空出一段平坦的调制器底噪，再往上才是噪声上扬。来源采样率的推断方式与 PCM 相同。高频很弱、只跌了 15–20dB 的 CD 式硬截止也会计入，条件是核心过渡段 ≤1.2kHz，且截止以上的底噪起伏 ≤1.5dB。
- **可检出范围**：报告给出调制噪声比最低点高出 20dB 的频率。高于这里的 PCM 截止会被噪声淹没，所以“未见 PCM 截止”只能说明来源不低于对应采样率，或者是原生 DSD。大致来说，DSD64 能分辨 44.1/48kHz 来源，88.2/96kHz 来源只有部分能分辨；DSD128 能分辨到 96kHz 左右；DXD（352.8kHz）来源一般看不出。
- **DSD 升频**：低倍率 DSD 经 PCM 中转再重新调制时，旧调制器的噪声包会留下来。在 1/6 倍频程的噪声曲线上表现为：先隆起，回落 ≥6dB，再被新调制器的噪声抬起。如果中转用的低通比较宽，回落可能落在分析范围之外，就看不出来。

许多正规 SACD 也在 PCM/DXD 中剪辑或做母带，“PCM 来源”不等于造假。22.05kHz 附近的硬截止通常说明母带是 CD 规格。DSD 文件不做 48kHz 差分。

## 加工链检查（`--check-sr`）

有些高解析音源并不是简单的软件升频。它们的超声部分不是空的，所以上面的截止检测会把它们判成“像真高解析”。但这层超声是某条固定的加工流程（例如“回放后用 192kHz 设备重录”）加上去的，不是原始录音里的。这样的加工链会在它经手的每个文件上留下同样的指纹：

- **固定尖峰**：对准采样率分数的窄带单音，例如 192kHz 的 48kHz（fs/4）和 72kHz（3fs/8）。这是转换设备的固有杂音，音乐里不会有。
- **超声细节形状**：30kHz 以上的频谱去掉大趋势后剩下的细小起伏。真实录音之间互不相关；同一条链做出来的文件则彼此相关。

加上 `--check-sr`，程序会把文件和内置的、以及你自己学习的指纹逐一比对。不加则不做这项检查，结果和以前完全一样。

```bash
hirescheck "歌曲.flac" --check-sr
hirescheck ~/Music --check-sr -j 2
hirescheck --list-chains                        # 列出可用的指纹
```

**判定规则：**

| 情况 | 结论 |
| --- | --- |
| 指纹里的尖峰全部达到门槛，形状相关 ≥ 0.15 | 吻合，可能性**很高** |
| 尖峰全部达到门槛，形状相关不到 0.15 | 吻合，可能性**较高** |
| 指纹允许只看形状（学习时每个文件的留一法形状相关都 ≥ 0.3），且形状相关 ≥ 0.3 | 吻合，可能性**较高** |
| 只有部分尖峰，或只有形状接近 | 只在技术细节里注明“部分特征吻合”，不改变结论 |

尖峰必须全部出现才算数：2L 的一首 192k 原生录音在 48kHz 就出现过一根 7.9dB 的尖峰，但 72kHz 没有。

吻合时，原来判为“像真高解析”“高频像噪声”“高解析意义不大”“无法判断”的文件，结论改为“超声部分可能不是原始录音”。已判为升频的文件，在结论后补一句“和加工链吻合”。汇总表多一列 `chain`，标签显示为“疑似加工链：名字”。

### 内置指纹：192k 加工链 A

用 14 个带同一来源标记（comment 标签）的 192kHz FLAC 学习，来自 13 张专辑，录音年代 1988–2019。共同尖峰在 48kHz 和 72kHz，匹配门槛分别是 11.2dB 和 8.7dB。这条链的形状指纹偏弱（留一法最低 0.10），不允许只凭形状判定。

| 文件 | 48kHz 尖峰 | 72kHz 尖峰 | 形状相关 | 结果 |
| --- | --- | --- | --- | --- |
| 学习用的 14 首（留一法，模板里不含被测的那首） | 14.2–30.0 dB | 11.7–23.7 dB | 0.10–0.70 | 14/14 吻合 |
| 没有来源标记、但疑似同一来源的 2 首 | 14.5、20.9 dB | 13.1、13.8 dB | 0.56、0.50 | 2/2 吻合 |
| 2L 原生录音（192k，5 张专辑） | −0.0 – 7.9 dB | −0.2 – 1.8 dB | 0.00–0.09 | 0/5 |
| 其他来源的 192k 文件（已能判为升频） | 0.1–2.5 dB | 0.3–1.4 dB | −0.01–0.01 | 0/6 |

从频谱图看，这条链出的文件，乐器泛音大多到 22kHz 左右就没了，往上只有一层跟着鼓点起伏的“雾”。所以内置指纹的结论是“原始音源大概不高于 48kHz”。

**局限：** 对照组只有 2L 一家的录音和少量升频文件。用同一类 192k 设备做的真录音，也可能带有相同的尖峰。吻合只能说明“和学习用的那批文件经过同一种加工”，说不出是回录、AI 还是别的方式。对方如果换了设备或改发其他采样率，指纹就会失效，需要重新学习。

### 学习新的加工链（`--learn-chain`）

如果你确认某批文件出自同一个来源，可以用它们学一条新指纹：

```bash
hirescheck --learn-chain "某平台 96k" 专辑A 专辑B 专辑C            # 文件夹会递归扫描
hirescheck --learn-chain "某平台 96k" *.flac --chain-note "某平台 2023 年后上架的 hi-res"
```

**对文件的要求**，不满足会直接报错并说明原因：

- **至少 5 个文件**，来自**至少 3 个不同的文件夹（专辑）**，建议 10 个以上。只用一张专辑学到的，可能只是这张专辑自己的母带特征。
- **采样率必须相同**，且不低于 88.2kHz：一条指纹只对应一种采样率。
- 只能用 PCM 无损文件，不能用 DSD 或有损文件。
- 这批文件要有共同指纹：至少 2 根每首都高出 9dB 以上的共同尖峰，或者每个文件的留一法形状相关都 ≥ 0.3。都没有时会拒绝保存。例如拿 5 首互不相干的 2L 录音来学，就会被拒绝。

学习时会逐个文件打印留一法形状相关和尖峰强度。每根尖峰的匹配门槛取学习样本里最弱的值减 3dB，并限制在 8–12dB 之间。指纹保存在 `~/.config/hirescheck/chains/名字.json`，也可以用 `--out` 指定路径；重装或卸载 hirescheck 都不会删掉它。学完以后，最好拿几首确定不属于这条链的文件试一下，确认不会误报。

## 48kHz 转换差分是什么

将选定片段降到 48kHz，再升回原采样率，补偿群延迟、保持原始电平，然后与原片段相减。使用约 110dB 阻带抑制的线性相位 FIR，通带到 20kHz、阻带从 24kHz 起，每段两端各排除 50ms，减少边界影响。比较过程在浮点数中进行，不额外引入整数 PCM 量化。

- **全频段残差**：包括被丢弃的超声信息、20–24kHz 过渡带的变化和滤波误差。
- **20Hz–20kHz 残差**：更直接反映这次转换对常见可听频段的影响。用原信号和残差的 Welch 功率谱在该频段内积分求比值。

差分值是**能量比的分贝**。例如 -60dB 对应原信号能量的百万分之一，RMS 幅度约为千分之一。dBFS 按样本幅度 1 为参考，满幅正弦的 RMS 为 -3.01dBFS；PSD 的 dBFS/Hz 则是每赫兹谱密度，不能直接当成总音量。

差分越小，说明**这次指定转换**改变得越少。差分只覆盖选段，不代表所有采样点；它也无法排除播放设备滤波、非线性或不同母带造成的差别。若要回答“我能不能听出明显差异”，应使用同一母带、电平匹配的版本做随机双盲 ABX。

脚本退出码：`0` 分析完成；`1` 解码、计算或写入失败（批量检查时表示至少有一个文件出错，或者没找到可检查的文件）；`2` 命令参数错误；`130` 被 Ctrl-C 中断（已完成的报告保留，但不生成汇总）。

## 回归测试

`tests/` 里有一套带预期结果的合成样本：
- PCM：各种升频、偏缓滤波器、线性插值、多级链路、暗录音、原生录音、有损式低通，以及 MP3/AAC 转码；
- DSD：PCM 来源分为 44.1k/48k/96k/192k，各做 DSD64 和 DSD128 两种；另有原生 DSD 和 DSD64→DSD128 升频。

生成 DSD 样本需要 C 编译器（用来编译 `tests/sdm.c` 里的 1-bit 调制器）。

```bash
python tests/make_corpus.py /tmp/corpus        # 约 30 秒，写入约 200MB
python tests/run_tests.py /tmp/corpus           # 加 -v 显示每个截止的细节
python tests/run_tests.py /tmp/corpus --real-dsd "/路径/确认是CD母带的SACD专辑"
```

手上有确认没有升频的真实高解析录音时，可以用它派生出一组伪造版本：经 44.1/48/88.2/96kHz 中转、多级链路、MP3/AAC/Opus 转码，以及 DSD64/DSD128。`run_tests.py` 会自动读取派生目录里的 `expected.json`：

```bash
python tests/derive_from_source.py "/路径/真实192k录音.flac" /tmp/derived   # 默认截取 60–120 秒
python tests/run_tests.py /tmp/derived
```

标为 KNOWN 的是物理上难以检出的情况，例如 DSD64 里的 96kHz 来源、经宽带 DXD 中转的 DSD 升频。它们只报告，不计为失败。

加工链指纹没有可以随仓库分发的样本，需要用你自己的文件测试。每个列表文件每行写一个路径：

```bash
python tests/check_chains.py --chain chain-192k-a --match 已知是这条链.txt --no-match 原生录音和其他来源.txt -v
```

`--match` 里的文件必须和指定的指纹吻合，`--no-match` 里的文件不能和任何指纹吻合。2L 的免费测试曲目（原生 192k/352.8k 录音）适合放进 `--no-match`。这些音频受版权保护，不要提交到仓库里。

代码检查用 ruff：`ruff check hirescheck tests`。GitHub Actions 会在 Linux 和 macOS、Python 3.10 和 3.13 上跑 ruff、合成样本和回归测试。
